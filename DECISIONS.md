# Decisions

Settled choices and standing constraints. Do not re-open an active entry; supersede it with a new one and mark the old one `superseded by D-…`.

- [D-20261018-01] One self-hosted community per install; all neighborhood specifics are configuration/data, never code — reusable by other neighborhoods (status: active)
- [D-20261018-02] Stack is PHP 8.3 + Symfony 7.4 LTS, PostgreSQL 17 via DBAL (no ORM), Twig, vanilla JS/CSS without a build step, Leaflet, Docker Compose; no React/Redis/PostGIS — small, auditable, low-ops (status: active)
- [D-20261018-03] First verified email wins and publishes immediately; ownership is the `claims` primary key taken with INSERT … ON CONFLICT DO NOTHING; disputes are manual — owner's product choice (status: active)
- [D-20261018-04] Passwordless only: 15-minute single-use links consumed by CSRF-protected POST; 30-minute server-enforced idle sessions (5–240 configurable, env > YAML > default); no remember-me — owner policy (status: active)
- [D-20261018-05] Email-sending endpoints require browser SHA-256 proof-of-work AND persistent PostgreSQL rate limits; PoW is never the only defense (status: active)
- [D-20261018-06] Geometry is validated and evaluated server-side in PHP (edge-inclusive point-in-polygon); no PostGIS for < 1,000 homes (status: active)
- [D-20261018-07] (Redacted: the first deployment's own plat layout and naming.) Reference geometry came from official county recorded-plat polygons with each plat a separate zone and the amenity plat non-claimable (status: superseded by D-20261019-01, D-20261019-02)
- [D-20261018-08] House pins come only from reviewed inventories (county address points / CSV with coordinates) or resident-placed pins on allow-listed streets inside the approved boundary; never geocoded guesses or polygon centroids (status: active)
- [D-20261018-09] Routes are a suggested stop ORDER split by organizer-verified walkable groups; provider walking paths only after crossings are verified; never connect separate groups (status: active)
- [D-20261018-10] Repository stays private; public release, license confirmation (MIT proposed) and live deployment each need an explicit owner go-ahead (status: active)
- [D-20261018-11] Release route: private GitHub repo carries the development history while it stays private; a future public release is built as a separate scrubbed tree (status: superseded by D-20261019-03)
- [D-20261018-12] Tile requests send only the site origin as Referer (strict-origin-when-cross-origin) because the OSM tile policy requires one; /auth pages use same-origin (status: active)
- [D-20261018-13] Module-structure check code_root deviation accepted: Symfony requires browser code under public/ and migrations/config/scripts outside src/ (measured 73.3 % under src/ vs 80 % target) — framework convention outranks the heuristic (status: active)
- [D-20261018-14] Tests are organized by behaviour/acceptance criterion (e.g. AuthAndClaimFlowTest) rather than one file per class; the module-structure check's filename-matching testability heuristic reads 11.4 %, while measured line coverage is 93 % — traceability to acceptance tests is preferred (status: active)
- [D-20261019-01] Example geometry comes only from official recorded-plat polygons fetched by `scripts/fetch_arcgis_boundaries.py` with a reviewed source config; each plat phase is a zone, amenity/common plats are non-claimable zones outside the residential boundary, and imported boundaries stay unapproved until the organizer approves (status: active)
- [D-20261019-02] No real deployment data is committed — community names, locations, geometry, street names, address inventories, screenshots or host names of the owner's own neighborhood live only in git-ignored `deploy/private/<id>/`; the repository ships the fictional Maple Hollow demo and the Ventura Reserve (Orlando) example built from Orange County open data, with addresses fetched locally, never committed (status: active)
- [D-20261019-03] The repository history itself carries no private data so it can be made public by switching visibility; earlier history was rebuilt from a scrubbed tree, and the pre-scrub history is kept only as an offline bundle in `deploy/private/` (status: active)
- [D-20261019-04] Two roles: ROLE_USER (verified resident; manages only own homes) and ROLE_ADMIN (organizer; everything), granted only by `app:admin:grant` or `ORGANIZER_EMAILS`; declared on controllers with #[IsGranted] in addition to access_control; resident data only via owner-scoped `ResidentHomes` (DBAL QueryBuilder, no ORM); no voters until a second resident permission exists — ADR 0009 (status: active)
- [D-20261019-05] Abuse budgets are spent only by work actually done (mail sent, valid review request); organizers are exempt from the global sign-in cap; IPv6 clients are keyed by /64; mailbox aliases share a budget; honeypot fields on every form; email-sending endpoints answer no faster than AUTH_RESPONSE_FLOOR_MS after proof-of-work (status: active)
- [D-20261019-06] A resident manages at most `registration.max_homes_per_user` homes (default 2, organizer-editable; organizer transfers are exempt); an organizer's hide is kept on the address and survives release/re-claim (status: active)
- [D-20261019-07] nginx trusts X-Forwarded-For/-Proto only from loopback and its own network gateway (the published 127.0.0.1 port) plus NGINX_TRUSTED_PROXIES; production accepts only the APP_BASE_URL host; containers run with no-new-privileges, dropped capabilities, read-only roots where possible and resource limits; backups are 0600 and exclude session rows (status: active)
- [D-20261019-08] (superseded by D-20261019-16) Appearance follows the browser/system setting (prefers-color-scheme) with no in-app toggle; all colours are semantic tokens in app.css and dark mode changes tokens only, never layout; OSM tiles are softened by a CSS filter in dark mode (status: superseded)
- [D-20261019-09] No consent banner: the site has no analytics, ads or tracking and sets only a strictly necessary sign-in cookie after the user asks for it; local storage holds only the visitor's own preferences on their device; third-party loading is limited to OpenStreetMap tiles, disclosed in /privacy. Privacy, terms and accessibility pages are linked on every page; WCAG 2.1 AA is enforced by automated axe checks (status: active)
- [D-20261019-10] Script and stylesheet URLs carry the version and a fingerprint of all asset files (`/assets/v<version>.<hash>/…`) and are cached for a year; no cache (browser, CDN or tunnel edge) can mix old and new modules (status: active)
- [D-20261019-11] Shared links carry only changed filters, stop ids, an optional starting home and a manual-order flag; the visitor's location is used only in memory, never stored, sent or put in a link, and offered only in a secure context (status: active)
- [D-20261019-12] Areas without homes are handled with zone status (`coming_soon` drawn but not listable, `hidden` not public at all), not by editing geometry (status: active)
- [D-20261019-13] Self-entered addresses may require organizer approval (`registration.review_new_addresses`); waiting listings are hidden with moderation_reason `pending_review`, and the organizer's unhide is the approval (status: active)
- [D-20261019-14] Community-specific geometry corrections are importer configuration (`reassign` from an official layer, with a required note) kept with the community's private config; never hand-drawn and never in code (status: active)
- [D-20261019-15] Release notes shown in the app come from CHANGELOG.md at runtime; the source link comes from APP_SOURCE_URL (default: the project repository; empty hides it) (status: active)
- [D-20261019-16] Appearance defaults to the system setting; a visitor may choose Light or Dark and Larger text, More contrast or Reduce motion in the header's Appearance panel. Choices live only in that browser (`nhm:appearance`), are applied before paint, and never override the device's own accessibility settings; dark mode still changes tokens only, never layout (supersedes D-20261019-08) (status: active)
- [D-20261019-17] Trick-or-treat reminders ship as a built-in default list; an organizer's own list (up to 12 lines) replaces it entirely rather than being merged (status: active)
