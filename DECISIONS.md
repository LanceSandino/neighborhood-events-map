# Decisions

Settled choices and standing constraints. Do not re-open an active entry; supersede it with a new one and mark the old one `superseded by D-…`.

- [D-20261018-01] One self-hosted community per install; all neighborhood specifics are configuration/data, never code — reusable by other neighborhoods (status: active)
- [D-20261018-02] Stack is PHP 8.3 + Symfony 7.4 LTS, PostgreSQL 17 via DBAL (no ORM), Twig, vanilla JS/CSS without a build step, Leaflet, Docker Compose; no React/Redis/PostGIS — small, auditable, low-ops (status: active)
- [D-20261018-03] First verified email wins and publishes immediately; ownership is the `claims` primary key taken with INSERT … ON CONFLICT DO NOTHING; disputes are manual — owner's product choice (status: active)
- [D-20261018-04] Passwordless only: 15-minute single-use links consumed by CSRF-protected POST; 30-minute server-enforced idle sessions (5–240 configurable, env > YAML > default); no remember-me — owner policy (status: active)
- [D-20261018-05] Email-sending endpoints require browser SHA-256 proof-of-work AND persistent PostgreSQL rate limits; PoW is never the only defense (status: active)
- [D-20261018-06] Geometry is validated and evaluated server-side in PHP (edge-inclusive point-in-polygon); no PostGIS for < 1,000 homes (status: active)
- [D-20261018-07] (Redacted: the first deployment's own plat layout and naming.) Reference geometry came from official county recorded-plat polygons with each plat a separate zone and the amenity plat non-claimable (status: superseded by D-20261019-01, D-20261019-02)
- [D-20261018-08] House pins come only from reviewed inventories (county address points / CSV with coordinates) or resident-placed pins on allow-listed streets inside the approved boundary; never geocoded guesses or polygon centroids (status: active)
- [D-20261018-09] Routes are a suggested stop ORDER split by organizer-verified walkable groups; provider walking paths only after crossings are verified; never connect separate groups (status: active)
- [D-20261018-10] Repository stays private; public release, license confirmation (MIT proposed) and live deployment each need an explicit owner go-ahead (status: active; the license is settled by D-20261021-24)
- [D-20261018-11] Release route: private GitHub repo carries the development history while it stays private; a future public release is built as a separate scrubbed tree (status: superseded by D-20261019-03)
- [D-20261018-12] Tile requests send only the site origin as Referer (strict-origin-when-cross-origin) because the OSM tile policy requires one; /auth pages use same-origin (status: active)
- [D-20261018-13] Module-structure check code_root deviation accepted: Symfony requires browser code under public/ and migrations/config/scripts outside src/ (measured 73.3 % under src/ vs 80 % target) — framework convention outranks the heuristic (status: active)
- [D-20261018-14] Tests are organized by behaviour/acceptance criterion (e.g. AuthAndClaimFlowTest) rather than one file per class; the module-structure check's filename-matching testability heuristic reads 11.4 %, while measured line coverage is 93 % — traceability to acceptance tests is preferred (status: active)
- [D-20261019-01] Example geometry comes only from official recorded-plat polygons fetched by `scripts/fetch_arcgis_boundaries.py` with a reviewed source config; each plat phase is a zone, amenity/common plats are non-claimable zones outside the residential boundary, and imported boundaries stay unapproved until the organizer approves (status: active)
- [D-20261019-02] No real deployment data is committed — community names, locations, geometry, street names, address inventories, screenshots or host names of the owner's own neighborhood live only in git-ignored `deploy/private/<id>/`; the repository ships the fictional Maple Hollow demo and the Ventura Reserve (Orlando) example built from Orange County open data, with addresses fetched locally, never committed (status: active)
- [D-20261019-03] The repository history itself carries no private data so it can be made public by switching visibility; earlier history was rebuilt from a scrubbed tree, and the pre-scrub history is kept only as an offline bundle in `deploy/private/` (status: active)
- [D-20261019-04] Two roles: ROLE_USER (verified resident; manages only own homes) and ROLE_ADMIN (organizer; everything), granted only by `app:admin:grant` or `ORGANIZER_EMAILS`; declared on controllers with #[IsGranted] in addition to access_control; resident data only via owner-scoped `ResidentHomes` (DBAL QueryBuilder, no ORM); no voters until a second resident permission exists — ADR 0009 (status: active)
- [D-20261019-05] Abuse budgets are spent only by work actually done (mail sent, valid review request); organizers are exempt from the global sign-in cap; IPv6 clients are keyed by /64; mailbox aliases share a budget; honeypot fields on every form; email-sending endpoints answer no faster than AUTH_RESPONSE_FLOOR_MS after proof-of-work (status: active)
- [D-20261019-06] A resident manages at most `registration.max_homes_per_user` homes (default 2, organizer-editable; organizer transfers are exempt); an organizer's hide is kept on the address and survives release/re-claim (status: active)
- [D-20261019-07] nginx trusts X-Forwarded-For/-Proto only from loopback and its own network gateway (the published 127.0.0.1 port) plus NGINX_TRUSTED_PROXIES; production accepts only the APP_BASE_URL host; containers run with no-new-privileges, dropped capabilities, read-only roots where possible and resource limits; backups are 0600 and exclude session rows (status: active)
- [D-20261019-08] (superseded by D-20261019-16) Appearance follows the browser/system setting (prefers-color-scheme) with no in-app toggle; all colours are semantic tokens in app.css and dark mode changes tokens only, never layout; OSM tiles are softened by a CSS filter in dark mode (status: superseded)
- [D-20261019-09] No consent banner: the site has no analytics, ads or tracking and sets only a strictly necessary sign-in cookie after the user asks for it; local storage holds only the visitor's own preferences on their device; third-party loading is limited to OpenStreetMap tiles, disclosed in /privacy. Privacy, terms and accessibility pages are linked on every page; WCAG 2.1 AA is enforced by automated axe checks (status: active; optional cookie-free analytics added by D-20261021-34)
- [D-20261019-10] Script and stylesheet URLs carry the version and a fingerprint of all asset files (`/assets/v<version>.<hash>/…`) and are cached for a year; no cache (browser, CDN or tunnel edge) can mix old and new modules (status: active)
- [D-20261019-11] Shared links carry only changed filters, stop ids, an optional starting home and a manual-order flag; the visitor's location is used only in memory, never stored, sent or put in a link, and offered only in a secure context (status: active)
- [D-20261019-12] Areas without homes are handled with zone status (`coming_soon` drawn but not listable, `hidden` not public at all), not by editing geometry (status: active)
- [D-20261019-13] Self-entered addresses may require organizer approval (`registration.review_new_addresses`); waiting listings are hidden with moderation_reason `pending_review`, and the organizer's unhide is the approval (status: active)
- [D-20261019-14] Community-specific geometry corrections are importer configuration (`reassign` from an official layer, with a required note) kept with the community's private config; never hand-drawn and never in code (status: active)
- [D-20261019-15] Release notes shown in the app come from CHANGELOG.md at runtime; the source link comes from APP_SOURCE_URL (default: the project repository; empty hides it) (status: active)
- [D-20261019-16] Appearance defaults to the system setting; a visitor may choose Light or Dark and Larger text, More contrast or Reduce motion in the header's Appearance panel. Choices live only in that browser (`nhm:appearance`), are applied before paint, and never override the device's own accessibility settings; dark mode still changes tokens only, never layout (supersedes D-20261019-08) (status: active)
- [D-20261019-17] Trick-or-treat reminders ship as a built-in default list; an organizer's own list (up to 12 lines) replaces it entirely rather than being merged (status: active)
- [D-20261019-18] Release cadence: each feedback round that adds features ships as its own minor pre-release (0.N.0-beta.1, then -beta.2… for fixes); fix-only rounds bump the pre-release number; one tag per tested round, never a large catch-all beta (status: active)
- [D-20261019-19] Visitors see one "big scares" concept (jump scares or an intense setup) in filters and tags; residents still record both details (status: active)
- [D-20261019-20] The project is named neighborhood-events-map (renamed from neighborhood-halloween-map) because it will cover more neighborhood events (Christmas next); one install still serves one community (status: active)
- [D-20261020-02] The family page is one page: map, My route (inline under the map; between map and list on phones) and the list; bottom tabs are Map · Rules · My house; the route offers Share and Show on map, no copy-as-text; visitors may keep named saved routes, each with its own saved homes, filters, start and order, stored only on their device (status: active)
- [D-20261020-03] The public map dims everything outside the approved boundary and limits panning and zooming out to the neighborhood plus a margin; route lines are drawn only from a configured walking-path provider (ADR 0007), never as straight lines (status: active)
- [D-20261021-01] Desktop and phones share one compact control design: no summary cards; quick filters (candy, sensory-friendly, 21+, saved) are icon + count buttons named by visually hidden text and a title; other filters live behind Filters; filter changes fit the map to the matching homes (owner request; status: active)
- [D-20261020-04] Releases are published as public multi-arch images on GitHub Container Registry (app and nginx; vX.Y.Z → :X.Y.Z and :latest, main → :edge) with an SBOM and a signed build-provenance attestation; servers pin APP_IMAGE_TAG and pull instead of building, and building from source stays supported with the same image names (status: active)
- [D-20261021-11] PHP-FPM never listens on a TCP port: nginx reaches it only through Unix sockets in a volume that only the app and nginx containers mount; the two email-sending endpoints run in their own small pool so the response floor (D-20261019-05) can never hold the map's workers. This also removes the stale-upstream 502, so the variable-upstream approach of the unmerged fix/nginx-upstream-reresolve branch (its D-20261020-01) is not needed (status: active)
- [D-20261021-12] Request paths are canonical: no route uses percent-encoding, so nginx (400) and the app (CanonicalPathSubscriber, 404) refuse any encoded path before guards, sessions or routing run; nginx rate-limit keys use the normalized $uri (status: active)
- [D-20261021-13] A claim or review request that names a registry address by id must also name its house number; a bare or mismatched id answers exactly like an unknown id, so sequential ids reveal no address text (status: active)
- [D-20261021-14] Hidden zones (D-20261019-12) are invisible in refusals too: a registry row in a hidden zone answers like an unknown id, pins inside one get an unnamed zone_not_open, a hidden key is unknown_zone; coming-soon zones keep their named refusal (status: active)
- [D-20261021-15] When the global sign-in budget is full, organizers get the same 429 as everyone else while their link is still sent: organizers are never locked out (D-20261019-05) and the reply never tells who is one (status: active)
- [D-20261021-16] Addresses use only ASCII letters, digits, spaces and . , ' - # (refused otherwise, never silently stripped); all other free text passes Shared/TextInput (valid UTF-8, NFC, no control or invisible text-reordering characters, length cap) before it is stored; output is still always escaped (status: active)
- [D-20261021-17] Zone names are placed automatically (pole of inaccessibility, overlaps resolved by priority) unless an organizer pins one with zones[].label_at; placed names never move (status: active)
- [D-20261021-18] The product is the "neighborhood events map"; the community's event is the setting `event.name` (default Halloween, the first supported event type) and code never hard-codes a holiday in titles, branding or emails. Persisted or deployed identifiers stay as they are: the `halloween` Compose project, database and user defaults, `halloween-*.dump` backup names, `nhm:*` local-storage keys, the `nhm_session` cookie, the `nhm` CSRF token id, the `X-NHM-Background` header, migration descriptions and the GHCR image names — renaming them would orphan volumes, backups, saved routes or sessions (status: active; owner confirmed 2026-10-21; the session cookie over HTTPS is refined by D-20261021-26)
- [D-20261021-19] New event types (Christmas lights, garage sale) are generic, code-defined event-type modules selected by `event.type` in the community settings; each defines its listing fields, filters, statuses, copy and icons on the PHP and JavaScript sides; organizers configure them but cannot define new field types, so validation stays on the server and labels stay accessible — ROADMAP.md (status: active; owner confirmed 2026-10-21)
- [D-20261021-20] One install still serves one community with one active event at a time; claims (address ownership) are independent of the event and survive switching events; each listing belongs to one event season (status: active; owner confirmed 2026-10-21)
- [D-20261021-21] Type-specific listing fields are stored in a server-validated `details` JSONB column on `listings` while the core fields (address, dates, hours, status, note, publication and moderation) stay relational columns; today's Halloween columns are copied into `details` and kept until the following minor release so a rollback still works (status: active; owner confirmed 2026-10-21)
- [D-20261021-22] Multi-day events have a date range with daily hours; a listing chooses its own subset of days and hours; "open now" is evaluated in the community time zone (status: active; owner confirmed 2026-10-21)
- [D-20261021-23] The new event types ship without photo uploads, contact details or payment handles on listings, and garage-sale notes are checked on the server for phone numbers, emails and payment handles — privacy and moderation load for volunteer organizers (status: active; owner confirmed 2026-10-21)
- [D-20261021-24] The project is released under the MIT license (LICENSE and composer.json agree), as the owner confirmed on 2026-10-21 (status: active)
- [D-20261021-25] The Ventura Reserve example keeps Orange County's public open-data plat polygons (source and terms recorded in its README, no address points); the owner accepted the county's reuse terms on 2026-10-21 (status: active)
- [D-20261021-26] Over HTTPS the session cookie is named `__Host-` + `SESSION_COOKIE_NAME` automatically (Secure, Path=/, no Domain); plain-HTTP installs and names that already carry a `__Host-`/`__Secure-` prefix keep their name. Upgrading signs current HTTPS sessions out once (sessions last at most 12 h anyway) (status: active)
- [D-20261021-27] nginx keys its request and connection limits on the client network the app uses (`$client_net`: IPv4 address, IPv6 /64, IPv4-mapped as IPv4); one network keeps at most 6 requests in PHP (half the default www pool) and 2 on the email endpoints (half the mail pool); static files keep 40 (status: active)
- [D-20261021-28] Account deletions, erased review requests and organizer-role changes go to an append-only account ledger (ids and times only); `bin/restore.sh` exports it before a restore, merges it back and replays it, and an entry only touches rows created at or before it, so a restore never revives a deleted account or a revoked organizer (status: active)
- [D-20261021-29] Every base image (Dockerfile stages, COPY --from, Compose and CI service images) is pinned by its multi-arch digest; Dependabot's docker and docker-compose ecosystems propose new digests (status: active)
- [D-20261021-30] Nothing of a boundary that is not approved is public — neither its outline nor its extent (`map.bbox` is null); until approval the public map opens on the configured center or the boundary's middle (status: active)
- [D-20261021-31] No GET changes state or writes a record: the claims export (which writes an audit event) is a CSRF-checked POST from a form button (status: active)
- [D-20261021-32] "Sign out everywhere" sets `users.sessions_ended_at`; IdleSessionSubscriber ends every session that began at or before it. Residents use the My house button, organizers `app:user:sign-out <email>` (status: active)
- [D-20261021-33] nginx directives use only named regex captures (map regexes run after location matching and overwrite $1…$9), and the development overlay mounts the checkout's nginx config so every local and end-to-end test runs the current one (status: active)
- [D-20261021-34] Analytics stay off by default. An operator whose site Cloudflare proxies may set `CLOUDFLARE_WEB_ANALYTICS=1` to let Cloudflare's injected, cookie-free Web Analytics beacon run: the Content-Security-Policy then also allows `https://static.cloudflareinsights.com` (reports go to the site's own `/cdn-cgi/rum`), and the footer and privacy page disclose it. The app never embeds the beacon itself; still no cookies, no consent banner. Cloudflare is one optional way to deploy (docs/examples/cloudflare.md), never a requirement (status: active)
- [D-20261021-35] The privacy notice lists every cookie and storage the site uses and why there is no cookie banner (all strictly necessary or kept on the device); `CLOUDFLARE_PROXY=1` (or Web Analytics) adds that Cloudflare carries requests and may set its strictly necessary security cookies `__cf_bm` and `cf_clearance`; it names the organizer's email delivery service; its "Last updated" date is fixed and changed only with the text (status: active)
